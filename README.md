# Sweet Roses — мини-приложение для MAX (и Telegram)

Демо-версия от «Цифровые решения для бизнеса». Одно и то же приложение работает в **MAX** и в **Telegram** — мессенджер выбирается настройкой `MESSENGER`.

## Запуск в MAX (Amvera)

1. **Бот в MAX:** business.max.ru → профиль (самозанятый/ИП/юрлицо, проверка через Госуслуги) → «Чат-боты» → создать бота → скопировать токен.
2. **Сервер:** загрузить плоскую сборку (`python3 build-flat.py папка`) в проект Amvera. В «Переменных» добавить секрет `MAX_BOT_TOKEN` (токен вставляете сами) и `MESSENGER=max`.
3. **Адрес приложения:** в кабинете MAX → «Чат-боты» → бот → ⋮ → «Настройки» → вставить адрес проекта (`https://….amvera.io`), тип кнопки «Открыть» → «Сохранить».
4. **Стать администратором:** открыть бота в MAX → «Старт». Первый нажавший становится администратором: в приложении появится шестерёнка, заявки будут приходить ему в MAX. Команда `/id` показывает ваш ID в MAX.
5. **Проверка:** оформить тестовую заявку из приложения — она придёт в чат с ботом.

Технически: Bridge `https://st.max.ru/js/max-web-app.js`, подпись данных запуска проверяется на сервере (`server/max.js`), Bot API `https://platform-api2.max.ru` (long polling). Если сервер не может достучаться до API MAX из-за сертификата — положите сертификат «Russian Trusted Root CA» в `certs/russian_trusted_root_ca.pem` (или путь в `MAX_CA_FILE`).


## Привлечение новых покупателей

- **«Намекнуть»** — на товаре: покупатель отправляет подарок тому, кто должен его подарить; получатель открывает ссылку прямо на этом товаре с плашкой «Анна намекает…».
- **«Поделиться»** — отправить товар в любой чат; поделившийся засчитывается как пригласивший.
- **Цифровая открытка** — «Это подарок» при оформлении: получатель открывает открытку с текстом и получает бонусы на первый заказ.
- **Ссылки и QR-коды** (админка → «Ссылки и QR») — отдельная ссылка/QR на каждое место рекламы, видно, сколько пришло и заказало.
- **Приветственный подарок** — бонусы каждому новому покупателю (по ссылке друга — бонус друга, по открытке — бонус открытки).
Формат параметров запуска: `p_<товар>`, `h_<товар>`, `r_<код>`, `s_<источник>`, `g_<открытка>` через «-».

## Лояльность и оплата (в админке → «Бонусы и оплата»)

Клиентская база, бонусы (с уровнями и сгоранием), важные даты с напоминаниями, повтор заказа, «приведи друга», рассылки по группам (только с согласием), оплата в приложении: **демо** (без денег, для показа) или **ЮKassa** (ключи магазина в переменных `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`; адрес уведомлений в кабинете ЮKassa — `https://<адрес>/api/pay/yookassa`). Каждую функцию можно выключить. Фоновые задачи (сгорание, напоминания, отмена неоплаченных через 60 минут) идут каждые 5 минут. Чеки 54-ФЗ через ЮKassa пока не передаются — добавить при подключении боевого магазина.

Проверки: `npm test` (55 тестов), браузерная проверка MAX-версии: `node mock/e2e-max.js` `node mock/e2e-loyalty.js` и `node mock/e2e-growth.js` (скриншоты в `mock/shots-max/`, `mock/shots-loyalty/`).

## Районы доставки и оплата переводом (сделано для Flowers Gagulya, 15.10.2026)

- **Районы доставки** — «Управление → Настройки → Районы доставки»: владелец сам добавляет районы, для каждого — цена, «бесплатно от» суммы и время в пути «от–до» минут. Покупатель при доставке сначала выбирает район: цена сразу в итоге, а на сегодня видны только те часы, к которым курьер успеет. Сервер всё пересчитывает сам. Нет районов — доставку считает менеджер, как раньше.
- **Оплата переводом на карту** — «Управление → Бонусы и оплата → Оплата переводом на карту»: номер карты и/или телефон СБП, банк, получатель. Режим «Сразу после заказа» (реквизиты видны сразу, можно платить ночью) или «После подтверждения» (реквизиты уходят клиенту в чат по кнопке «Подтвердить»). Клиент жмёт «Я оплатил(а)» → менеджерам уведомление → менеджер проверяет банк и жмёт «Оплата получена» → клиенту сообщение. Такие заказы не отменяются автоматически. Если включена онлайн-оплата (ЮKassa), перевод не показывается. Реквизиты в публичный каталог не попадают — только покупателю его заказа.
- **Фото в заявке** — менеджеру после текста заявки приходит фото заказанных товаров (в MAX — картинки по ссылке, в Telegram — альбом), в админке у заявки — миниатюры.
- **Новый магазин из своего «семени»**: `SEED=gagulya` — первый запуск с `seed/gagulya.seed.json` (бренд, чёрно-белая тема `theme: "mono"`, монограмма, районы, пример каталога с рисунками-заглушками из `public/demo/`). Плоская сборка: `SEED=gagulya python3 build-flat.py <папка>`.
- Проверки: `node --test test/gagulya.test.js`, браузерная — `node mock/e2e-gagulya.js` (скриншоты в `mock/shots-gagulya/`).

## Версия для Telegram

Мини-приложение мастерской клубники в шоколаде **Sweet Roses** (Иркутск): каталог из 106 товаров с сайта sweetroses-irk.ru, выбор шоколада, корзина с допами, промокод, оформление заявки и админ-панель.

Заявки приходят в Telegram менеджеру (сначала вам). Оплаты в приложении нет: менеджер перезванивает и выставляет счёт, как на сайте.

## Что внутри

| Папка | Что это |
|---|---|
| `public/` | само приложение (то, что видит покупатель) |
| `server/` | сервер: заявки, бот, админ-панель, статистика |
| `seed/catalog.seed.json` | каталог, собранный с сайта (используется при первом запуске) |
| `data/` | появится после запуска: каталог с вашими правками, заявки, статистика |
| `ЗАПУСТИТЬ ДЕМО.bat` | бесплатный запуск на вашем компьютере (Windows) |
| `deploy/install-ubuntu.sh` | установка на сервер одной командой |
| `test/` | автотесты (`npm test`) |

Внешних библиотек нет — нужен только Node.js 18+.

## Бесплатный показ клиенту — прямо с вашего компьютера (Windows)

Ничего арендовать не нужно. Приложение работает, пока компьютер включён и открыто окно запуска.

1. Дважды щёлкните **«ЗАПУСТИТЬ ДЕМО.bat»**.
   - При первом запуске скрипт сам поставит Node.js (если его нет) и скачает `cloudflared` — бесплатный туннель Cloudflare, который даёт приложению HTTPS-адрес.
   - Если Windows покажет «Система Windows защитила ваш компьютер» → **Подробнее** → **Выполнить в любом случае**.
2. Вставьте **токен бота** от @BotFather (правый клик в окне → Enter). Спросит один раз.
3. Откройте своего бота в Telegram → **/start** → «Открыть каталог». Вы — первый, кто нажал /start, поэтому станете **администратором** (шестерёнка в приложении), и заявки будут приходить вам.
4. Покажите клиенту: дайте ссылку на бота, пусть оформит тестовую заявку — она придёт вам в Telegram.

Важно: адрес туннеля меняется при каждом запуске — бот подхватывает его сам. Если закрыть окно или выключить компьютер, кнопка в боте перестанет открывать приложение до следующего запуска.

Когда клиент согласится — переезжайте на постоянный сервер (ниже), папку `data/` можно перенести вместе с заявками и правками.

## Постоянный запуск на сервере: 4 шага

### 1. Создайте бота в @BotFather
1. Откройте в Telegram **@BotFather** → `/newbot`.
2. Имя: например `Sweet Roses Иркутск`.
3. Никнейм — обязательно на `bot`, например `sweetroses_irk_bot`.
4. Скопируйте **токен** (вида `123456789:AA...`). Никому его не показывайте.

### 2. Арендуйте сервер (как у Георгия Риверы — Timeweb Cloud)
1. timeweb.cloud → **Облачные серверы** → **Создать**.
2. Система: **Ubuntu 24.04**, самая простая конфигурация (1 CPU, 1 ГБ) — её хватает.
3. После создания в карточке сервера будут **IP-адрес** и **пароль root**.

### 3. Загрузите проект и установите
На своём компьютере откройте терминал (Windows: PowerShell) в папке, где лежит архив:

```bash
scp sweetroses-miniapp.zip root@IP_СЕРВЕРА:/root/
ssh root@IP_СЕРВЕРА
```

На сервере:

```bash
apt-get install -y unzip && unzip sweetroses-miniapp.zip -d sweetroses && cd sweetroses
sudo bash deploy/install-ubuntu.sh
```

Скрипт поставит Node.js, бесплатный HTTPS (адрес вида `https://1-2-3-4.sslip.io`, свой домен не нужен) и запустит приложение как службу. В конце он напишет адрес мини-аппа.

### 4. Подключите бота и сделайте себя администратором
```bash
nano .env
```
- `BOT_TOKEN=` — вставьте токен из шага 1.
- Сохраните (Ctrl+O, Enter, Ctrl+X) и перезапустите: `systemctl restart sweetroses`.
- Напишите своему боту **/id** — он ответит вашим ID.
- Снова `nano .env`, впишите `ADMIN_IDS=ваш_ID`, перезапустите: `systemctl restart sweetroses`.

Готово. Откройте бота → `/start` → **«Открыть каталог»**. Внизу у бота появится кнопка **«Каталог»**.
Вам, как администратору, в шапке видна **шестерёнка** — это панель управления.

> Проверка: в панели **Настройки → «Отправить тестовую заявку себе»** — должно прийти сообщение от бота.

## Панель управления (шестерёнка)
- **Заявки** — все заявки, кнопки «Позвонить», «В работе», «Выполнена», «Отменена».
- **Товары** — поиск, изменить цену/фото/описание/категории, скрыть, поменять порядок, добавить новый, **«Обновить с сайта»** (подтянет новые товары и цены с sweetroses-irk.ru, ваши скрытия и порядок сохранятся).
- **Категории** — переименовать, скрыть, поменять порядок.
- **Допы и промо** — цены пакета, открытки и т.д.; промокоды (по умолчанию «Клубника» −5% на первый заказ).
- **Настройки** — заголовок и фото главной, телефон, адрес, часы, время готовности, тексты, **куда присылать заявки** (ID чатов через запятую — так переключите заявки на менеджера Sweet Roses; ID он узнает командой /id у бота).
- **Статистика** — посетители по дням, заявки, конверсия, популярные товары.

## Полезные команды на сервере
```bash
systemctl status sweetroses      # работает ли
journalctl -u sweetroses -f      # журнал
systemctl restart sweetroses     # перезапуск после правок .env
```
Резервная копия — папка `data/` (каталог, заявки, статистика).

## Посмотреть у себя на компьютере (без Telegram)
```bash
npm run dev
```
и откройте http://localhost:3000 — в этом режиме все видят админку, а бот выключен.

## Другие варианты размещения
- **Docker:** `docker build -t sweetroses . && docker run -d -p 3000:3000 --env-file .env -v $PWD/data:/app/data sweetroses` (HTTPS нужен отдельно).
- **Бесплатный Render.com** — не рекомендую: на бесплатном тарифе сервер засыпает (бот перестаёт отвечать) и стирает заявки при перезапуске.
